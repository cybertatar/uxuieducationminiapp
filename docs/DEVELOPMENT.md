# Разработка

Как устроен проект, как запустить его локально и выложить свою копию.

## Стек

Всё работает на бесплатном тарифе Cloudflare и живёт в одном воркере:

| Часть | Технология |
|---|---|
| Mini App | React + Vite, нативная тема Telegram (`web/`) |
| API и бот | Cloudflare Worker: Hono + grammY (`src/`) |
| База | Cloudflare D1 (SQLite) (`migrations/`) |
| Рассылки | Cron Trigger раз в минуту |
| Контент | TypeScript-файлы в `content/` |

## Локальная разработка

```bash
npm install
cp .dev.vars.example .dev.vars   # DEV_AUTH=1 пускает в API без Telegram
npm run dev                      # API на :8787, фронтенд на :5173
```

Откройте http://localhost:5173: приложение заработает под тестовым пользователем.
Боту нужен настоящий токен и публичный адрес, поэтому его удобнее проверять после деплоя.

```bash
npm test            # логика стриков, повторений, часовых поясов, авторизации и проверка контента
npm run typecheck
```

## Деплой (один раз)

1. **Бот.** В [@BotFather](https://t.me/BotFather): `/newbot` → сохраните токен.
2. **Cloudflare.** Зарегистрируйтесь на cloudflare.com (бесплатно), затем:
   ```bash
   npx wrangler login
   npx wrangler d1 create ux-quiz           # скопируйте database_id в wrangler.toml
   npx wrangler secret put BOT_TOKEN
   npx wrangler secret put WEBHOOK_SECRET   # любая длинная строка из букв, цифр, _ и -
   npm run deploy
   ```
3. Пропишите в `wrangler.toml` → `WEBAPP_URL` адрес, который выдал деплой (`https://ux-quiz.<ваш-аккаунт>.workers.dev`), и выполните `npm run deploy` ещё раз.
4. Откройте в браузере `https://<адрес>/bot/setup?secret=<WEBHOOK_SECRET>`. Это подключит вебхук, команды и кнопку меню.
5. В BotFather: `/newapp` (или Bot Settings → Configure Mini App) → укажите тот же URL.

Последующие обновления: `npm run deploy`.

## Как добавить вопрос

Вопросы лежат в `content/*.ts`, по файлу на трек; новый трек регистрируется в `content/index.ts` (и в `TrackId` в `content/types.ts`) и добавляется в один из разделов `sections` там же, его обложка — в `web/src/illustrations/`. Форматы вопросов:

**Обычный вопрос** (варианты текстом, картинка необязательна):

```ts
{
  id: 'h-040',                 // уникальный и неизменный: по нему хранится прогресс
  track: 'heuristics',
  topic: 'Видимость состояния системы',
  image: 'h-pay-double',       // необязательно: иллюстрация-сценарий
  text: 'Текст вопроса',
  options: ['Правильный', 'Неправильный 1', 'Неправильный 2', 'Неправильный 3'],
  correct: 0,                  // при показе варианты перемешиваются
  summary: 'Суть в одну строку — видна сразу после ответа',
  explanation: 'Полный разбор — виден сразу после ответа',
  fix: 'h-pay-loading',        // необязательно: картинка «как правильно»
  links: [{ title: 'NN/g: ...', url: 'https://...' }],
}
```

**Ответы-картинки** (`kind: 'image-choice'`): `options` — это ключи иллюстраций. Два варианта показываются как A/B, четыре — сеткой 2×2.

**«Тапни на проблему»** (`kind: 'hotspot'`): `image` — иллюстрация, `zone` — ключ зоны в ней (см. `zones` у иллюстрации).

**«Найди все проблемы»** (`kind: 'spot'`): `image` и список зон `zones`. Человек ставит столько меток, сколько зон, и ответ верен, если в каждой зоне есть метка. Зоны не должны стоять вплотную: тест проверяет, что между ними больше 20 единиц, иначе одна метка засчитается за две.

**«Расставь по порядку»** (`kind: 'order'`): `items` — от 3 до 6 пунктов в правильном порядке, на экране они перемешиваются, а человек тапает по ним 1, 2, 3… Подходит, только когда порядок однозначен.

**«Выбери все верные»** (`kind: 'multi'`): `options` и массив индексов `correct`. Засчитывается только точное совпадение. Хотя бы один вариант должен быть лишним. С `images: true` варианты — ключи иллюстраций.

В трёх последних механиках и в «тапни» верность считает приложение и отправляет 0 (верно) или 1 (нет). Вопросы с картинками и этими механиками бот в чате не задаёт, они есть только в приложении.

## Как добавить урок

Уроки «Учебника» лежат в `content/lessons/`, по файлу на трек, и собираются в `content/lessons/index.ts`. Урок — это пересказ статьи (NN/g, Laws of UX, Apple, Google, W3C, справка Figma) простыми словами для новичка, а не перевод: своими словами, с примерами из жизни и ссылкой на оригинал.

```ts
{
  id: 'l-heuristics-h1',        // уникальный и неизменный: по нему хранится отметка «прочитано»
  track: 'heuristics',
  title: 'Видимость состояния',
  description: 'Одна строка в списке уроков, до 90 символов',
  topics: ['Видимость состояния системы'],  // темы вопросов трека (поле topic), которые объясняет урок
  blocks: [
    { type: 'p', text: 'Абзац. Можно выделять **жирным**.' },
    { type: 'h', text: 'Подзаголовок' },
    { type: 'list', items: ['Пункт', 'Ещё пункт'] },
    { type: 'life', text: 'Пример из жизни: лифт, врач, аварийный выход' },
    { type: 'term', term: 'Эвристика', text: 'Объяснение термина простыми словами' },
    { type: 'image', image: 'h-stepper', caption: 'Подпись' },
    { type: 'compare', bad: 'h-upload-silent', good: 'h-upload-status', caption: 'Что не так и как лучше' },
  ],
  takeaways: ['2–4 тезиса для блока «Запомни главное»'],
  practice: ['h-003', 'h-041', 'h-066'],  // 3 вопроса из того же трека на закрепление
  sources: [{ title: 'NN/g: Visibility of System Status', url: 'https://...' }],
}
```

По `topics` экран результатов и блок «Что почитать» ведут из ошибки в нужный урок, рядом со ссылками на первоисточники. У каждой темы может быть только один урок. Время чтения считается само. Уроки одного трека стоят подряд в порядке изучения: после закрепления приложение ведёт на следующий урок, а после последнего — к вопросам по всей теме. Урок считается прочитанным, когда человек долистал до «Запомни главное» (таблица `lesson_reads`).

`npm test` проверит, что темы урока есть среди вопросов трека, вопросы на закрепление существуют и взяты из тем урока, иллюстрации есть, а вопросы не повторяют картинки из урока, иначе ответ угадывается по узнаванию.

### Иллюстрации

Вайрфреймы рисуются кодом в `web/src/illustrations/` из деталей `kit.ts` (экраны, поля, кнопки, иконки). Цвета задаются классами, поэтому картинки сами подстраиваются под светлую и тёмную тему Telegram. Все иллюстрации разом видны на странице `http://localhost:5173/gallery.html` при запущенном `npm run dev`.

Кот Кегль — пиксельный спрайт в `web/src/Cat.tsx`: один символ строки — один пиксель.

`npm test` проверит, что id уникальны, индексы корректны, все иллюстрации и зоны существуют, а у каждого вопроса есть суть, разбор и ссылка.

## Сообщения коммитов

Заголовок коммита виден на главной странице репозитория рядом с каждым файлом, поэтому он короткий и нейтральный, на английском: `Add share cards`, `Update lessons`, `Fix streak layout`. Повелительное наклонение, до 50 символов, без деталей и рассуждений. Подробности, если они нужны, пишутся в тело коммита и в описание PR: их видно в истории, но не на главной.

## Профиль бота

Описание бота (в пустом чате) и короткое описание (в профиле) задаются в `src/texts.ts` и применяются при каждом деплое через `/bot/setup`. Количество тем и вопросов подставляется автоматически.

Аватарки с котом лежат в `brand/`. Поставить аватарку можно только вручную: в @BotFather → `/setuserpic` → выбрать бота → отправить PNG.

### Гайд «как открыть тренажёр»

Многие не знают про мини-аппы и пишут боту в чат. Поэтому приветствие на `/start` уходит подписью к анимации, где показано, как открыть приложение кнопкой меню «Тренажёр». А на любое сообщение, кроме команд, бот отвечает подсказкой с кнопкой (`appHintText` в `src/texts.ts`).

Анимация — dev-страница `http://localhost:5173/onboarding.html` (`web/src/onboarding/`). Внутри настоящий экран приложения, поэтому после изменений главной гайд стоит перерендерить: запустить `npm run dev:web` и выполнить `node scripts/render-onboarding.mjs` (нужны Playwright с Chromium и ffmpeg). Получится `web/public/onboarding.mp4`: он раздаётся по адресу `/onboarding.mp4`, и бот берёт его оттуда. Скрипт также записывает хеш видео в `src/onboarding-version.ts`, а бот добавляет его к ссылке: Telegram кеширует файлы по адресу и без этого показывал бы старую версию. Закоммитьте оба файла.

Тот же скрипт рендерит вариант для описания бота, которое видно в пустом чате до «Старт»: `brand/onboarding-description.mp4` и `.gif` (640×360, вариант `?layout=wide`). В нём два шага — «Старт», затем «Тренажёр», потому что до «Старт» кнопки меню ещё нет. Поставить вручную: @BotFather → `/setdescriptionpic` → выбрать бота → отправить MP4 (если не примет — GIF).

## Карусель для Instagram

Слайды — dev-страница `http://localhost:5173/carousel.html` (`web/src/carousel/`): они собираются из настоящих компонентов приложения, поэтому числа тем, вопросов и иллюстраций всегда актуальны. Скриншоты экранов лежат в `web/src/carousel/shots/`.

## Поделиться

Результатом теста, стриком и уроком можно поделиться: кнопки на экране итогов, в календаре и в шапке урока.
Mini App просит у воркера `POST /api/share` подготовленное сообщение (`savePreparedInlineMessage`) и открывает нативный выбор чата через `WebApp.shareMessage` (Telegram 8.0+). В чат уходит картинка с подписью и кнопкой, которая открывает мини-апп по ссылке `t.me/<бот>?startapp=…`. Если сообщение подготовить не вышло (старый клиент, локальная разработка), открывается `t.me/share` с тем же текстом и ссылкой.

Тексты — `src/share.ts` (покрыты тестами), глаголы в них без рода: пол человека мы не знаем.

Картинку Mini App рисует сам на canvas по данным человека (`web/src/share-card.ts`): счёт и ответы по порядку, стрик за эту неделю, название урока. JPEG кодирует не `canvas.toDataURL`, а `jpeg-js`, чтобы файл был одинаковым на любом устройстве. JPEG уходит в том же запросе, воркер кладёт его в таблицу `share_images` и отдаёт Telegram по адресу `/share-img/<id>.jpg`. Через два дня cron удаляет строку: к этому времени Telegram уже скачал фото. Если с карточками что-то не так: Actions → «Диагностика карточек» → Run workflow покажет, подключён ли канал, и последние картинки по ссылке — размер, начало и конец файла (у целого JPEG — `FFD8…` и `FFD9`) и кто их загрузил. Примеры карточек, в том числе с длинным названием урока, — внизу dev-страницы `http://localhost:5173/share.html`.

**Канал для карточек.** Фото по ссылке Telegram на iPhone у отправителя сохранял обрезанным (у получателей и на компьютере всё было целым, после сброса кеша — тоже). Поэтому, если подключён закрытый канал, бот кладёт карточку туда и отправляет её обычным фото по `file_id`. Подключить: создайте закрытый канал и добавьте бота администратором. Бот запомнит канал сам (таблица `config`, ключ `share_chat`) и напишет в нём «Готово». Принимает он только канал, куда его добавил автор (`OWNER_USERNAME` в `src/bot.ts`), из остальных уходит. Если убрать бота из канала, шеринг вернётся к фото по ссылке.

Если карточка не нарисовалась, уходит запасная картинка без цифр из `web/public/share/*.jpg`: в ней нет ничего, что могло бы разойтись с подписью. Её макеты — вверху той же страницы (`web/src/share-cards/`). Чтобы перерендерить их, запустите `npm run dev:web` и выполните `node scripts/render-share.mjs` (нужен Playwright с Chromium). Telegram принимает для фото только JPEG.

Ссылка из урока ведёт прямо в урок: `startapp=<id урока>`, App открывает его вместо главной. Результат и стрик открывают главную с метками `share_result` и `share_streak`. Все три метки, как и любая другая, пишутся в `users.source` для новых пользователей, так что в статистике видно, сколько людей пришло по шерингу (у уроков метка начинается с `l-`).

## Уведомления

Вход в настройки — строка внизу карточки стрика на «Прогрессе» (пока ничего не приходит, она выделена акцентом и зовёт «Включить»), ячейка в календаре и `/settings` в боте. Кроме того, на экране итогов, пока уведомления не работают, появляется предложение включить напоминание о стрике в одно касание. Если отказаться, оно больше не показывается на этом устройстве.

Напоминание включено в базе по умолчанию, но бот может писать только тем, кто нажал «Старт» или дал разрешение (`can_message`). Поэтому приложение считает уведомления включёнными, только когда есть и то и другое (`web/src/notify.ts`), а при включении просит разрешение (`requestWriteAccess`).

## Статистика

**Метки источника.** Чтобы понять, откуда приходят люди, давайте ссылку с меткой: `t.me/uxuitrainer_bot?start=vc` (откроет чат с ботом) или `t.me/uxuitrainer_bot?startapp=vc` (сразу откроет мини-апп). В метке только латиница, цифры, `_` и `-`, до 64 символов. Она пишется в `users.source` один раз, когда человек приходит впервые.

**Журнал ответов.** Каждый ответ — строка в `answer_log`: вопрос, выбранный вариант (индекс в исходном `options`), верно ли и где ответили (`app` или `chat`).

**Сводка.** Actions → «Статистика» → Run workflow: пользователи, ответы, активность, источники и популярность тем появятся в Summary запуска. Репозиторий публичный, поэтому там только агрегаты, без имён и id.

Запросы к боевой базе: `npx wrangler d1 execute ux-quiz --remote --command "…"` из папки проекта.

```sql
-- откуда пришли и сколько из них ответили хотя бы раз
SELECT COALESCE(u.source, '—') AS source, COUNT(*) AS came, COUNT(a.user_id) AS answered
FROM users u LEFT JOIN (SELECT DISTINCT user_id FROM answer_log) a ON a.user_id = u.id
WHERE u.source IS NOT NULL OR u.created_at > (SELECT MIN(created_at) FROM answer_log)
GROUP BY source ORDER BY came DESC;

-- с чем путают правильный ответ: распределение выбранных вариантов по вопросу
SELECT question_id, option, correct, COUNT(*) AS n
FROM answer_log WHERE question_id = 'h-007' GROUP BY option ORDER BY n DESC;
```
